# Production Mechanics Matrix across Factory Games

This document surveys production mechanics across 13 factory, logistics, and colony-automation games (and overhaul modpacks) to inform the design of **GameData v4** (`docs/ROADMAP.md`, Decisions D5–D7).

---

## 0. Baseline: Current Data Model (`GameData` v3) & Linear Solver (`FactorySolver`)

In the current v3 data model ([`GameData.h`](file:///home/hagoel/Projects/factory-planner/src/core/data/GameData.h), [`Node.h`](file:///home/hagoel/Projects/factory-planner/src/core/graph/Node.h), [`FactorySolver.cpp`](file:///home/hagoel/Projects/factory-planner/src/core/graph/FactorySolver.cpp)):

- **`Recipe`** defines fixed `time_seconds` ($t_0 > 0$), fixed `input_ports` with base amounts $a_{i_k}$, and fixed `output_ports` with base amounts $a_{o_k}$.
- **`Machine`** defines only `base_crafting_speed` ($B > 0$).
- **`Node`** holds two hardcoded scalar modifiers: `clock_speed` ($C = \text{clock\_speed}/100$) and `production_multiplier` ($P = \text{production\_multiplier}/100$).
- **Linear Program (LP) Stoichiometry:** For each node, [`FactorySolver::addRecipeConstraints`](file:///home/hagoel/Projects/factory-planner/src/core/graph/FactorySolver.cpp#L748-L839) locks all input and output port rates $R_p$ into fixed linear proportions relative to a reference port $R_{\text{ref}}$:
  $$R_{i_k} = \frac{a_{i_k}}{a_{o_0} \cdot P} R_{o_0}, \qquad R_{o_k} = \frac{a_{o_k}}{a_{o_0}} R_{o_0}$$
- **Machine Count Derivation & Stage 2a/3a Weights:** [`FactorySolver::buildMachineActivityTerms`](file:///home/hagoel/Projects/factory-planner/src/core/graph/FactorySolver.cpp#L935-L1027) and [`FactorySolver::updateComponentGraph`](file:///home/hagoel/Projects/factory-planner/src/core/graph/FactorySolver.cpp#L1406-L1483) compute the machine count $M_n$ linearly from the solved reference port flow $R_{\text{ref}(n)}$:
  $$M_n = w_n \cdot R_{\text{ref}(n)}, \qquad w_n = \frac{t_0}{a_{\text{ref}} \cdot B \cdot U \cdot C}$$
  where $U \in \{1, 60, 3600\}$ converts `seconds`, `minutes`, or `hours`.

### Classification Categories (Decision D6)

1. **`PRE-SOLVE`:** Given the node's selected machine, recipe, user-configured node parameters, and graph-global settings, a deterministic expression evaluates **before** building the LP to yield constant per-node effective values:
   - Effective input port set $\mathcal{I}_n$ and per-craft amounts $a'_{i_k} \ge 0$
   - Effective output port set $\mathcal{O}_n$ and per-craft amounts $a'_{o_k} \ge 0$
   - Effective cycle time per machine-craft $t'_n > 0$ (or effective speed multiplier $S'_n > 0$)
   - Because $a'_{i_k}, a'_{o_k}, t'_n$ are constants during `FactorySolver::solve()`, the LP stoichiometry constraints and machine-activity weights $w_n$ remain **strictly linear**.
2. **`POST-SOLVE`:** Computed **after** the LP solves, as a function of the solved port flow rates $R_p$, wire flows $F_c$, and node machine counts $M_n$ (as well as node parameters and machine/recipe attributes). Used for node body readouts, tooltips, and graph-wide totals (e.g., MW, EU/t, Stress Units, Workers, Pollution, Maintenance).
3. **`NON-LINEAR`:** Couples flow variables or state variables across connections in a way that violates LP linearity (e.g., bilinear mixing of intensive properties like temperature/enthalpy, state-dependent efficiency where a node's stoichiometry depends on its own solved flow rate, integer machine rounding in the middle of a chain, or time-varying differential equations). For each, we document **why** it is non-linear and what **linear or pre-solve parameterization** approximates it.

| **M3** | **Somersloop Production Amplification** | Satisfactory (1.0+) | Slotting $k \in [0, K_{\max}]$ Somersloops into a machine with $K_{\max} \in \{1, 2, 4\}$ slots multiplies all recipe outputs without increasing inputs:<br>$P_{\text{sloop}} = 1 + \frac{k}{K_{\max}} \in [1.0, 2.0]$, so $a'_{o_j} = a_{o_j} \cdot P_{\text{sloop}}$, $a'_{i_j} = a_{i_j}$.<br>Power penalty scales quadratically with the output multiplier. | **`PRE-SOLVE`** (output amounts) & **`POST-SOLVE`** (power & sloop count) |

## 2. Must-Have Mechanics per Game (3–5 Core Mechanics for a Useful Planner)

### 2.1 Satisfactory
1. **Clock Speed (`clock_speed` $\in [1\%, 250\%]$) & Power Shards (M1, M2):** Linearly scales machine speed (`PRE-SOLVE`) and computes required Power Shards (`POST-SOLVE`).

## 3. Schema Requirements to Cover All `PRE-SOLVE` Mechanics

To express every `PRE-SOLVE` mechanic in Section 1 without hardcoding game-specific logic in C++, **GameData v4** needs four groups of schema constructs:

### 3.1 Graph / Game-Level Global Parameters (`globals`)
Used for tech-tree research levels, overhaul switches, and environmental cycles that apply across all nodes in a project unless overridden:
- `id`: string identifier exposed in expressions as `global.<id>` (e.g., `global.steel_prod_level`, `global.turd_ulric_branch`, `global.work_hours`, `global.wet_days`, `global.drought_days`).
- `type`: `float` | `int` | `bool` | `enum`.
- `default`, `min`, `max`, `options` (for `enum`), `label`, `group`.

### 3.2 Node Parameter Definitions (`parameters`)
Defined at the game level or attached to specific machine/recipe classes, instantiated per `Node` on the canvas (replacing the hardcoded `Node::clock_speed` and `Node::production_multiplier`), and exposed in expressions as `param.<id>`:

| Parameter Type | Example Node Parameters across Games | Schema Fields Needed |
|---|---|---|
| **`float`** | `clock_speed` ($1\dots 250\%$, Satisfactory), `tile_efficiency` ($0\dots 500\%$, Mindustry), `heat_supplied` (Erekir), `freshness_pct` (Factorio Gleba), `input_temp_c` (ONI), `crit_chance_pct` (AtS), `receiving_efficiency` (DSP) | `id`, `type: "float"`, `default`, `min` (constant or expression like `100 + 50 * param.shards`), `max`, `step`, `unit` (`"%"`, `"K"`, `"°C"`), `ui_widget` (`"slider"` \| `"drag"` \| `"input"`) |
| **`int`** | `somersloops` ($0\dots 4$, Satisfactory), `beacon_count` (Factorio), `parallel_limit` / `pa_machines` ($1\dots 64$, GTNH), `crop_growth` / `crop_gain` ($1\dots 31$, GTNH), `rpm` ($1\dots 256$, Create) | `id`, `type: "int"`, `default`, `min`, `max` (constant or expression like `machine.max_somersloops`), `ui_widget` (`"stepper"` \| `"slider"`) |
| **`bool`** | `boosted` (Mindustry drills), `domesticated` / `farmers_touch` (ONI), `graviton_lens` (DSP), `has_electricity` / `has_tractor` / `has_silo` (Anno 1800) | `id`, `type: "bool"`, `default`, `ui_widget: "checkbox"` |
| **`enum`** | `proliferator_mode` (`none`, `extra_products`, `speedup`, DSP), `overdrive` (`none`, `projector`, `phase`, `dome`, Mindustry), `voltage_tier` (`ULV`..`MAX`, GTNH), `coil_type` (`cupronickel`..`eternal`, GTNH), `purity` (`impure`, `normal`, `pure`, Satisfactory), `quality_tier` (`normal`..`legendary`, Factorio), `rain_engine` (`0`..`3`, AtS) | `id`, `type: "enum"`, `default`, `options`: list of `{ key, label, attributes: { ... } }` (so selecting `coil_type = "kanthal"` exposes `param.coil_type.heat = 2701` via table lookup!) |
| **`resource_choice`** | `fuel_key` (Burner fuel selector in Factorio / Pyanodons), `slot_1_resource` (Ingredient category choice in Against the Storm / GTNH OreDict), `specialist_input_override` (Anno 1800) | `id`, `type: "resource_choice"`, `allowed_tag` or `allowed_resources`, `default` (exposes selected resource's attributes, e.g., `param.fuel.fuel_value_mj`, `param.fuel.burnt_result`) |
| **`visible_if`** | Predicate expression controlling whether a parameter widget is shown on a given node (e.g., show `coil_type` only when `machine.uses_coils == 1`; show `somersloops` only when `machine.max_somersloops > 0`). | `visible_if`: boolean expression over `machine.*`, `recipe.*`, `param.*` |

### 3.3 Machine Attributes (`machine.*`)
Arbitrary typed key-value attributes (with schema defaults) on each `Machine` definition, readable in both `PRE-SOLVE` and `POST-SOLVE` expressions:
- `machine.base_speed` (`double`, default `1.0`): baseline crafting speed multiplier.
- `machine.base_power` (`double`, default `0.0`): active power draw (MW, kW, EU/t, SU/RPM, hp).
- `machine.idle_power` (`double`, default `0.0`): standby power draw (Factorio module/beacon drain).
- `machine.power_exponent` (`double`, default `1.0`): e.g. `1.321928` for Satisfactory production buildings vs. `1.0` for generators.
- `machine.tier` (`int`, default `0`): voltage/machine tier $T_{\text{mach}}$ (GTNH `0..14`).
- `machine.max_somersloops` / `machine.module_slots` (`int`, default `0`): slot capacity for amplification or modules.
- `machine.base_productivity` (`double`, default `0.0`): built-in productivity bonus (e.g., `+0.50` for Factorio Space Age Foundry / Biochamber / EM Plant).
- `machine.max_parallels` (`int` or expression, default `1`): maximum parallel crafts per cycle (GTNH multiblocks).
- `machine.perfect_oc` (`bool`, default `false`): whether the machine natively performs $4\times/4\times$ Perfect Overclocks (GTNH Large Chemical Reactor).
- `machine.uses_coils` (`bool`, default `false`): whether coil heat bonuses apply (GTNH EBF / Volcanus).
- `machine.heat_requirement` / `machine.max_efficiency` (`double`): Erekir `HeatCrafter` baseline heat and cap.
- `machine.fuel_category` / `machine.burner_efficiency` (`string`, `double`): enables dynamic fuel input port calculation.
- `machine.workers` / `machine.maintenance` / `machine.computing` (`double`): Captain of Industry / Anno 1800 / Timberborn workforce & service costs.

### 3.4 Recipe Attributes & Dynamic Port Definitions (`recipe.*`, `port.*`)
Each `Recipe` needs:
1. **Scalar Recipe Attributes (`recipe.*`):**
   - `recipe.base_time` ($t_0 > 0$).
   - `recipe.base_power` ($E_0$, e.g. GTNH recipe EU/t or Satisfactory variable power average/peak $W_{\min}, W_{\max}$).
   - `recipe.min_tier` ($T_{\text{rec}}$, GTNH voltage tier requirement).
   - `recipe.min_heat` ($H_{\text{rec}}$, GTNH Kelvin coil requirement or Create Blaze Burner heat level).
   - `recipe.allows_productivity` (`bool`, whether Factorio productivity modules or DSP Extra Products mode are permitted).
   - `recipe.crop_tier` / `recipe.bee_speed` (domain-specific constants for GTNH CropsNH / Bees).
2. **Pre-Solve Node Time Formula (`effective_time_expr`):**
   - Evaluates effective craft time $t'_n > 0$ per machine-batch from `recipe.*`, `machine.*`, `param.*`, and `global.*`.
   - If $t'_n \le 0$ or a gating condition (`recipe.enabled_expr`, e.g., `machine.tier >= recipe.min_tier && coil_heat >= recipe.min_heat`) evaluates to `false`, the solver clamps all ports on the node to $0$ (just as `clock_speed <= 0` does today).
3. **Pre-Solve Port Definitions (Inputs & Outputs):**
   Each port definition in `recipe.inputs` and `recipe.outputs` (plus optional **machine-injected ports** for fuels, boosters, proliferators, rainwater, or maintenance) needs:
   - `resource_key` (or `resource_key_expr` to support **M13** fuel choice, **M14** `burnt_result`, **M42** Anno specialist input replacement, and **M45** AtS ingredient category selection).
   - `base_amount` ($a_0 \ge 0$).
   - `catalyst_amount` ($a_{\text{cat}} \ge 0$, default `0.0`, excluded from productivity scaling per **M10**).
   - `is_catalyst` (`bool`, default `false`): if `true` (or if `effective_amount == 0` with `non_consumed == true` per **M31** GTNH programmed circuits/molds), the port does not generate an LP flow constraint and is rendered as a static setup requirement.
   - `enabled_expr` (optional boolean expression, default `true`): enables or disables the port before solving! Covers:
     - **M29** GTNH tier-gated byproducts (`machine.tier >= port.min_tier`)
     - **M22** Mindustry optional liquid boosters (`param.boosted == 1`)
     - **M18** DSP proliferator spray input port (`param.proliferator_tier > 0`)
     - **M40** ONI wild vs. domesticated plant irrigation (`param.domesticated == 1`)
     - **M43** Anno 1800 extra cycle byproduct (`param.extra_good_cycles > 0`)
     - **M46** Against the Storm rainwater input (`param.rain_engine > 0`)
   - `amount_expr` (optional expression, default `port.base_amount` for inputs and `(port.base_amount - port.catalyst_amount) * productivity + port.catalyst_amount` for outputs): evaluates the exact per-batch amount $a'_p \ge 0$ fed into [`FactorySolver::addRecipeConstraints`](file:///home/hagoel/Projects/factory-planner/src/core/graph/FactorySolver.cpp#L748-L839). Covers:
     - **M3** Somersloop amplification
     - **M11** Factorio quality probability weights
     - **M13/M14** Burner fuel & ash amounts
     - **M30** GTNH tier-boosted chance outputs (`port.base_amount * min(1.0, port.base_chance + port.tier_chance_bonus * max(0, machine.tier - recipe.min_tier))`)
     - **M33/M34** GTNH CropsNH (`1.03 ^ param.crop_gain`) and Forestry Bees (`min(1.0, 0.028 * (port.base_chance ^ 0.52) * ((param.housing_mod + param.housing_tier) ^ 0.52) * (param.bee_speed ^ 0.37))`).
