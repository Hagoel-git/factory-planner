# 1.1 Pre-Release Codebase Audit

This document contains the verified technical analysis of the 5 user-noted issues (Part 0) followed by a comprehensive pre-release codebase audit across **Potential Bugs / Edge Cases (Category 1)**, **Redundancy / Dead Code (Category 2)**, and **Performance / Polish (Category 3)** under a strict 1.0 feature freeze.

## Execution Strategy & Phased Batches (Phase 0 Decisions)

### Core Philosophy: Simplicity Over Overengineering
> [!IMPORTANT]
> **Avoid Overengineering**:
> Simple, targeted fixes (3–10 lines) that directly solve the root cause are strictly preferred over complex abstractions, new helper layers, or architectural rewrites. Reusing existing mechanisms (such as the existing `m_editorsToClose` dialog queue and `weakly_canonical` filesystem checks) eliminates regressions and minimizes points of failure.

### Aligned Design Decisions (Phase 0)
1. **Window Group `X` Button**: When the tab group close button is clicked, queue all open tabs in that dock node for closing, reusing the existing `m_editorsToClose` flow (which already prompts for unsaved changes in `Close All`). Fallback if edge cases arise: hide group close button via `ImGui::GetStyle().DockingNodeHasCloseButton = false;`.
2. **Docking Layout Persistence**: Store the docking layout in a dedicated file (`docking_layout.ini`) alongside `app_settings.json` in the executable/app directory, avoiding cluttering user project folders with a raw `imgui.ini`. Add a `Window -> Reset Layout` menu item to restore defaults.
3. **Animation Pacing**: Add an `Application::hasActiveAnimations()` query tracking active flow duration (`"Z"`), navigation zoom (`"F"`), and toast notifications. Keep full 60 FPS while animating, then drop immediately to low-power idle. Fix the Wayland double-sleep bug.
4. **Quadtree Bounds Crash**: Dynamically calculate world bounds encompassing all nodes with padding (minimum 262,144 units). Rebuild/expand automatically when a node is placed or dragged outside bounds, and guard against non-finite (`FLT_MAX`) coordinates.
5. **Input Validation Philosophy (Maximum Freedom)**: Only restrict/clamp fields where invalid values cause crashes, `NaN`, `Inf`, or broken solver states. Allow user freedom otherwise. In the LP solver, handle `0.0%` multiplier safely by fixing craft and input rates to 0 rather than allowing infinite resource consumption.
6. **Same-Name Different-Folder Tabs**: Compare `std::filesystem::weakly_canonical` paths so identically named files in different folders can be opened simultaneously. When two open tabs share the same stem, display parent folder qualifiers (e.g., `Project (folderA)` vs `Project (folderB)`).

## Part 0: Deep-Dive into the 5 User-Noted Issues

### Issue 1: Same Name in Different Folders Cannot Open Because of Existing Tab Message (and Duplicate Tab Names)

#### Root Cause Analysis
There are four interconnected places in [`src/app/Application.cpp`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp) where open editors are identified solely by their filename stem (`editor->getName()`) instead of their full project path (`editor->getProjectFilePath()`):

1. **[`Application::validateNewEditor`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1280-L1300) checks `editor->getName() == name` instead of comparing filesystem paths**:
   ```cpp
   bool Application::validateNewEditor(const std::string &name, const std::filesystem::path &location) {
       bool nameExists = std::any_of(m_editors.begin(), m_editors.end(), [&](const auto &editor) {
           return editor->getName() == name;
       });

       if (nameExists) {
           VLOG(1) << "Editor with name '" << name << "' already exists.";
           m_showFileAlreadyOpenPopup = true;
           return false;
       }
   ```
   When `/folderA/factory.fpp` is open (`editor->getName() == "factory"`), opening `/folderB/factory.fpp` passes `name = "factory"` (`path.stem().string()`) to `createNewEditor` ([`Application.cpp:456, 985-986`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L985-L986)). `validateNewEditor` sees `nameExists == true`, triggers the `"FileAlreadyOpen"` popup ([`Application.cpp:192-205`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L192-L205)), and refuses to open the second file.

2. **[`Application::drawNewProjectDialog`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L908-L910) blocks creating a project with the same stem name in another directory**:
   ```cpp
   bool nameExists = std::any_of(m_editors.begin(), m_editors.end(), [&](const auto &editor) {
       return editor->getName() == projectNameStr;
   });
   ```
   This disables the `"Create"` button ([`line 919`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L919)) and shows `"An editor with this name already exists."` ([`lines 953-956`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L953-L956)) even when `fullPath` is in a completely different folder.

3. **Duplicate ImGui window IDs (`###` + `editor->getName()`), missing tab/modal disambiguation in [`Application::draw`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L165-L171) and [`Application.cpp:217-218`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L217-L218), and `ed::Begin(m_editorName.c_str())` in [`FactoryNodeEditor::draw`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L131)**:
   ```cpp
   std::string windowTitle = editor->getName();
   if (editor->isDirty()) {
       windowTitle += " *";
   }
   windowTitle += "###" + editor->getName();
   
   ImGui::Begin(windowTitle.c_str(), &is_open, editorWindowFlags);
   ```
   Because the ID suffix after `###` is `editor->getName()`, two open projects with the same stem name (`"factory"`) in different folders receive the **exact same ImGui window ID (`###factory`)**, causing Dear ImGui to merge both tabs into the same window! Furthermore:
   - The visible tab title before `###` does not disambiguate duplicate stem names (unlike `Open Recent` in [`Application::drawMenuBar`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L432-L444), which already computes `nameCounts[stem] > 1` and appends `" (" + file.parent_path().filename().string() + ")"`).
   - The `"Unsaved Changes"` modal at [`Application.cpp:217-218`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L217-L218) only prints `m_currentEditorToClose->getName().c_str()`, which is ambiguous when multiple dirty tabs share the same stem name in different folders.
   - [`FactoryNodeEditor::draw()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L131) passes `m_editorName.c_str()` to `ed::Begin(m_editorName.c_str(), ImVec2(0.0f, 0.0f))` (though each editor has its own `ed::EditorContext* m_context` and is scoped inside the outer `ImGui::Begin(windowTitle.c_str())` window).

4. **[`Application::drawSaveAsDialog`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1079-L1092) and [`Application::closeEditorByName`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1523-L1531) close unrelated open tabs that share the same stem name AND fail to close dirty overwritten tabs synchronously**:
   ```cpp
   std::string newFileName = std::filesystem::path(path).stem().string();

   // Check for duplicate names among other open tabs
   auto* currentEditor = (m_activeEditor >= 0 && static_cast<size_t>(m_activeEditor) < m_editors.size())
                             ? m_editors[m_activeEditor].get() : nullptr;
   bool nameExists = std::any_of(m_editors.begin(), m_editors.end(), [&](const auto &editor) {
       return editor.get() != currentEditor && editor->getName() == newFileName;
   });

   if (nameExists) {
       closeEditorByName(newFileName);
   }
   saveActiveEditorAs(path, SaveAsMode::SwitchToNewFile);
   ```
   - First, if `/folderA/factory.fpp` is open and the user saves another tab as `/folderB/factory.fpp`, [`closeEditorByName("factory")`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1523-L1531) matches by `editor->getName()` instead of file path and closes `/folderA/factory.fpp`!
   - Second, [`Application::closeEditorByName`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1523-L1531) calls `requestCloseEditor(static_cast<int>(i))` ([`line 1526`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1526)). If the other open tab being overwritten has **unsaved changes** (`isDirty() == true`), `requestCloseEditor(i)` ([`Application.cpp:1165-1174`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1165-L1174)) **does not close the tab synchronously**—it only sets `m_showUnsavedChangesDialog = true` for the next frame! Then `saveActiveEditorAs(path, SaveAsMode::SwitchToNewFile)` executes immediately on line 1091, overwriting the file on disk while the old tab stays open and pops up an `"Unsaved Changes"` modal (where clicking `"Save"` would overwrite the newly saved file right back, and clicking `"Cancel"` leaves two open tabs pointing to the exact same file!).

#### Recommended Fix
1. **Compare normalized/canonical file paths in `validateNewEditor`, `drawNewProjectDialog`, and `drawSaveAsDialog`**:
   ```cpp
   bool Application::validateNewEditor(const std::string &name, const std::filesystem::path &location) {
       if (location.empty() || !std::filesystem::exists(location.parent_path())) {
           LOG(ERROR) << "Invalid location: " << location;
           NotificationManager::instance().addNotification("Invalid Project Location",
               "The specified project location is invalid or does not exist.",
               NotificationType::Error);
           return false;
       }

       std::error_code ec;
       auto targetPath = std::filesystem::weakly_canonical(location, ec);
       bool fileAlreadyOpen = std::any_of(m_editors.begin(), m_editors.end(), [&](const auto &editor) {
           std::error_code edEc;
           return std::filesystem::weakly_canonical(editor->getProjectFilePath(), edEc) == targetPath;
       });

       if (fileAlreadyOpen) {
           VLOG(1) << "Editor for file '" << location << "' already exists.";
           m_showFileAlreadyOpenPopup = true;
           return false;
       }
       return true;
   }
   ```
   - Apply the same `weakly_canonical(editor->getProjectFilePath(), ec) == weakly_canonical(fullPath, ec)` check in [`Application::drawNewProjectDialog`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L908-L910).
   - Replace `closeEditorByName(const std::string &name)` ([`Application.cpp:1088, 1523-1531`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L1523-L1531)) with `closeEditorByPath(const std::filesystem::path &targetPath)` that compares `weakly_canonical` paths and **force-closes** the overwritten tab synchronously via `closeEditor(static_cast<int>(i))` (not `requestCloseEditor`), since the user has already explicitly confirmed overwriting the file in the Save As confirmation modal.
2. **Use the full project path for the ImGui window ID (`###`) and disambiguate duplicate stem names in [`Application::draw`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L150-L171) and [`Application.cpp:217-218`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L217-L218)**:
   Count `nameCounts[ed->getName()]++` before the editor loop (matching [`Application::drawMenuBar:432-444`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L432-L444)):
   ```cpp
   std::string windowTitle = editor->getName();
   if (nameCounts[editor->getName()] > 1) {
       windowTitle += " (" + editor->getProjectFilePath().parent_path().filename().string() + ")";
   }
   if (editor->isDirty()) {
       windowTitle += " *";
   }
   windowTitle += "###" + editor->getProjectFilePath().string();
   ```
   Also include the parent folder or full path in the `"Unsaved Changes"` modal prompt at [`Application.cpp:217-218`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L217-L218).

### Issue 2: Do Not Apply FPS Reduction While Animation Is Playing (e.g., Show Flow `"Z"`) or Improve Background CPU Preservation

#### Root Cause Analysis
In [`src/app/main.cpp`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L29-L30), the main loop drops into an idle power-saving mode `0.5s` after the last user input event:
- At [`main.cpp:69-85`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L69-L85), `checkUserInteraction()` only checks whether a mouse button is down, the mouse wheel/cursor moved this frame, or a keyboard key is currently held down (`ImGui::IsKeyDown`).
- At [`main.cpp:226-245`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L226-L245):
  ```cpp
  double currentTime = glfwGetTime();
  bool wasIdle = (currentTime - lastActivityTime) > IDLE_THRESHOLD_SECONDS;
  bool isIdle = wasIdle;

  if (!isIdle) {
      glfwPollEvents();
  } else {
      glfwWaitEventsTimeout(IDLE_POLL_TIMEOUT_SECONDS);
  }
  ...
  if (checkUserInteraction()) {
      lastActivityTime = glfwGetTime();
      isIdle = false;
  }
  ```
- Furthermore, on Linux Wayland ([`main.cpp:266-276`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L266-L276)):
  ```cpp
  #if __linux__
      // fix for Wayland: Application not responding with vsync enabled, so we use a manual frame rate control
      if (is_wayland) {
          if (!isIdle) {
              framePacer.pace();
          } else {
              std::this_thread::sleep_for(std::chrono::duration<double>(IDLE_POLL_TIMEOUT_SECONDS));
              framePacer.reset();
          }
      }
  #endif
  ```
This causes three problems:
1. **Animations stutter after 0.5 seconds**:
   In [`FactoryNodeEditor.cpp:56`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L56), `ed_style.FlowDuration = 6.0f;` (6.0 seconds). When the user taps `Z` ([`FactoryNodeEditor::showFlow()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L328-L332)) or `F` ([`FactoryNodeEditor::fitView()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L334-L378)), or when a toast notification is active in [`NotificationManager::draw()`](file:///home/hagoel/Projects/factory-planner/src/services/NotificationManager.cpp#L41-L138), `checkUserInteraction()` returns `false` as soon as the key/mouse is released. After `0.5s` (`IDLE_THRESHOLD_SECONDS`), `isIdle` becomes `true`, throttling the remaining **5.5 seconds** of the `"Show Flow"` animation (and toast fade animations) down to 5–10 FPS!
2. **Double-sleep on Wayland when idle**:
   On Wayland, when `isIdle` is `true` and no input events arrive, the loop waits `0.1s` in `glfwWaitEventsTimeout(IDLE_POLL_TIMEOUT_SECONDS)` at [`line 233`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L233) **and** sleeps another `0.1s` in `std::this_thread::sleep_for(...)` at [`line 272`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L272), compounding the idle frame time to `0.2s` (**5 FPS**).
3. **Minimized (`GLFW_ICONIFIED`) window is not checked**:
   [`main.cpp`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L226-L274) never checks `glfwGetWindowAttrib(window, GLFW_ICONIFIED)`, so minimizing the window while an animation is active would keep rendering at 60 FPS in the background.

#### Recommended Fix
1. **Track active animations in `FactoryNodeEditor`, `NotificationManager`, and `Application`**:
   - In [`FactoryNodeEditor`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.h), record `double m_animationEndTime = 0.0;`:
     - In [`FactoryNodeEditor::showFlow()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L328-L332), if `!m_graph->getConnections().empty()`, set `m_animationEndTime = std::max(m_animationEndTime, glfwGetTime() + static_cast<double>(ed::GetStyle().FlowDuration));` (`6.0s`).
     - In [`FactoryNodeEditor::fitView()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L334-L378), set `m_animationEndTime = std::max(m_animationEndTime, glfwGetTime() + static_cast<double>(ed::GetStyle().ScrollDuration));` (`0.35s` in [`imgui_node_editor.h:169`](file:///home/hagoel/Projects/factory-planner/external/imgui-node-editor/imgui_node_editor.h#L169)).
     - Expose `bool isAnimating() const { return glfwGetTime() < m_animationEndTime; }`.
   - In [`NotificationManager.h`](file:///home/hagoel/Projects/factory-planner/src/services/NotificationManager.h), add `bool hasActiveNotifications() const { return !m_notifications.empty(); }`.
   - In [`Application`](file:///home/hagoel/Projects/factory-planner/src/app/Application.h), add `bool hasActiveAnimations() const` returning `true` if `NotificationManager::instance().hasActiveNotifications()` is true or if the active `FactoryNodeEditor` (or any visible editor) returns `editor->isAnimating()`.
2. **Prevent idle throttling while `app.hasActiveAnimations()` is true (unless minimized) and eliminate the double-sleep on Wayland**:
   - Note that `app.draw()` is called at [`main.cpp:255`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L255), **after** the initial `isIdle` and `checkUserInteraction()` checks (`lines 228-245`). Therefore, `app.hasActiveAnimations()` must be checked **both** at the top of the loop (before `glfwWaitEventsTimeout` at line 233) **and** after `app.draw()` (before the Wayland end-of-frame sleep at lines 268–275) so that animations/notifications triggered inside `app.draw()` on an idle frame immediately exit idle mode.
   - Check `bool isIconified = glfwGetWindowAttrib(window, GLFW_ICONIFIED) != 0;`. If `isIconified` is true, force `isIdle = true` and skip `app.hasActiveAnimations()` so minimized windows always sleep.
   - On Wayland ([`main.cpp:268-275`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L268-L275)), only sleep for the remaining time if `glfwWaitEventsTimeout` woke up early, or use a secondary `FramePacer idlePacer(10.0)` instead of stacking an unconditional `0.1s` `sleep_for` on top of `glfwWaitEventsTimeout(0.1)`.

### Issue 3: Is It Possible to Preserve Docking Layout After App Restart?

#### Root Cause Analysis
Yes, it is possible. Currently, three explicit settings in the codebase prevent Dear ImGui from saving and restoring the docking layout across restarts:

1. **`io.IniFilename = nullptr` in [`src/app/main.cpp:196`](file:///home/hagoel/Projects/factory-planner/src/app/main.cpp#L196)**:
   ```cpp
   io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;
   io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;
   io.IniFilename = nullptr;
   ```
   Setting `io.IniFilename = nullptr` completely disables Dear ImGui's automatic `.ini` layout serialization.
2. **Redundant and destructive `!m_dockInitialized` `DockBuilder` block in [`Application::draw`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L137-L148)**:
   ```cpp
   ImGuiID dockspace_id = ImGui::GetID("MainDockSpace");
   ImGui::DockSpace(dockspace_id, ImVec2(0.0f, 0.0f), dockspace_flags);

   if ((ImGui::GetIO().ConfigFlags & ImGuiConfigFlags_DockingEnable) && !m_dockInitialized) {
       ImGui::DockBuilderRemoveNode(dockspace_id);
       ImGui::DockBuilderAddNode(dockspace_id, host_flags | ImGuiDockNodeFlags_DockSpace);
       ImGui::DockBuilderSetNodeSize(dockspace_id, viewport->Size);

       ImGui::DockBuilderFinish(dockspace_id);

       m_dockInitialized = true;
   }
   ```
   - First, `ImGui::DockSpace(dockspace_id, ...)` on [`line 138`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L138) **already creates and sizes the `dockspace_id` node automatically** if it does not exist in ImGui's dock context (see [`external/imgui/imgui.cpp:20356-20362`](file:///home/hagoel/Projects/factory-planner/external/imgui/imgui.cpp#L20356-L20362): `if (node == NULL) { node = DockContextAddNode(&g, dockspace_id); node->LocalFlagsInWindows |= ImGuiDockNodeFlags_DockSpace; ... }`).
   - Second, because lines 140–148 do not perform any `DockBuilderSplitNode` or `DockBuilderDockWindow` calls, all that block does on the first frame is **destroy** the dock tree (including any layout loaded from `imgui.ini`) via `DockBuilderRemoveNode(dockspace_id)` and recreate an empty root node!
   - Third, `host_flags | ImGuiDockNodeFlags_DockSpace` bitwise-ORs `ImGuiWindowFlags` (`ImGuiWindowFlags_NoDocking | ImGuiWindowFlags_NoDecoration | ImGuiWindowFlags_NoMove | ...`) into an `ImGuiDockNodeFlags` parameter, aliasing internal `ImGuiDockNodeFlags` bits (`ImGuiDockNodeFlags_NoSplit`, `ImGuiDockNodeFlags_NoResize`, etc.) and corrupting the dockspace node's flags.
   - Note: Checking `ImGui::DockBuilderGetNode(dockspace_id) == nullptr` **after** `ImGui::DockSpace()` on line 138 would be dead code because `ImGui::DockSpace()` on line 138 guarantees the node is non-null by line 140.
3. **`ImGuiWindowFlags_NoSavedSettings` on every editor tab in [`Application::draw`](file:///home/hagoel/Projects/factory-planner/src/app/Application.cpp#L163)**:
   ```cpp
   ImGuiWindowFlags editorWindowFlags = ImGuiWindowFlags_NoCollapse | ImGuiWindowFlags_NoSavedSettings;
   ```
   Even if `.ini` saving is enabled and `DockBuilderRemoveNode` is removed, `ImGuiWindowFlags_NoSavedSettings` instructs ImGui **not** to record or restore the dock node ID, split ratio, or window state for any editor tab!

#### Recommended Fix

1. **Sanitize `FLT_MAX` / non-finite node positions and compute centered power-of-two `worldBounds` dynamically in `FactoryNodeEditor::rebuildQuadtree()`**:

   ```cpp
   void FactoryNodeEditor::rebuildQuadtree() {
       float maxAbsCoord = 0.0f;

       std::vector<NodeQuadtreeData> items;
       items.reserve(m_graph->getNodes().size());

       for (const auto &node : m_graph->getNodes()) {
           ed::NodeId nodeId = IdUtils::toNodeId(node.id);
           ImVec2 nodePos = ed::GetNodePosition(nodeId);
           if (!std::isfinite(nodePos.x) || !std::isfinite(nodePos.y) ||
               std::abs(nodePos.x) >= FLT_MAX * 0.5f || std::abs(nodePos.y) >= FLT_MAX * 0.5f) {
               nodePos = ImVec2(0.0f, 0.0f);
               ed::SetNodePosition(nodeId, nodePos);
           }
           ImVec2 nodeSize = ed::GetNodeSize(nodeId);
           if (!std::isfinite(nodeSize.x) || !std::isfinite(nodeSize.y) ||
               nodeSize.x <= 0.0f || nodeSize.y <= 0.0f) {
               nodeSize = ImVec2(300.0f, 100.0f);
           }
           maxAbsCoord = std::max({maxAbsCoord,
                                   std::abs(nodePos.x),
                                   std::abs(nodePos.y),
                                   std::abs(nodePos.x + nodeSize.x),
                                   std::abs(nodePos.y + nodeSize.y)});
           items.emplace_back(node.id, nodePos, nodeSize);
       }

       const float margin = 2048.0f;
       float halfWorldSize = 131072.0f; // 2^17 minimum half-size
       while (halfWorldSize <= maxAbsCoord + margin && halfWorldSize < (1.0f * (1ULL << 30))) {
           halfWorldSize *= 2.0f;
       }
       float worldSize = halfWorldSize * 2.0f;

       quadtree::Box<float> worldBounds(
           quadtree::Vector2<float>(-halfWorldSize, -halfWorldSize),
           quadtree::Vector2<float>(worldSize, worldSize)
       );
       m_nodeQuadtree = std::make_unique<quadtree::Quadtree<NodeQuadtreeData, GetNodeBox>>(worldBounds);

       for (const auto &item : items) {
           m_nodeQuadtree->add(item);
       }
   }
   ```
   Apply the same `FLT_MAX` / `std::isfinite` guard on `ed::GetNodePosition(nodeId)` inside [`FactoryNodeEditor::fitView()`](file:///home/hagoel/Projects/factory-planner/src/editor/factory_planner/FactoryNodeEditor.cpp#L348-L356).
2. **Keep currently dragged/selected nodes visible during drag**:
   In `FactoryNodeEditor::drawNodes()`, if `m_draggingNodes` is true, insert `IdUtils::fromNodeId(m_draggedNodeId)` (and any selected nodes) into `visibleNodeIds` even if their pre-drag position is outside `viewBox`.
